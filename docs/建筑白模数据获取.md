> 编写时间：2026-11-04　对应提交：`a73e56c`

## 0. 一句话结论

白模取不到**不是代码 bug，是网络出口问题**：三个 Overpass 镜像里有俩直接超时，第三个把**所有请求（连 `/api/status` 都算）**都返回 `406 Not Acceptable`。代码捕获异常后静默降级成程序生成白模，所以面板上显示的是「程序生成 · N 栋」而不是「OSM 真实建筑轮廓 · N 栋」。

推荐落地顺序：**本地静态 JSON（兜底，离线可用）→ OpenFreeMap 矢量瓦片（实测可达、免 key、带高度字段）→ 后端代理 Overpass**。

## 1. 现在代码里白模是怎么来的

### 1.1 两条路径，一个入口

```
MapView.onMounted()
  └─ loadCity(city)                        // 故意不 await，不阻塞装配
       ├─ await city.buildFromOsm({ bbox: OSM_BBOX })      ← 路径 A：真实轮廓
       │     └─ fetchOsmBuildings(bbox)                    ← overpass.js
       │           ├─ readCache()   命中 → 直接返回（0 网络请求）
       │           └─ 未命中 → 依次试 3 个镜像 → writeCache()
       │     └─ for 每栋：过滤 → completeHeight() → addBuilding()
       │     └─ sim.setDataSource('OSM 真实建筑轮廓 · N 栋')
       │
       └─ catch → city.build()                             ← 路径 B：程序生成
             └─ 16×13 网格、随机留白 18%、中心区加高
             └─ sim.setDataSource('程序生成 · N 栋')
```

两条路径最终都调 `addBuilding({ ring, height, name, code })`，所以下游的**编码、拾取、弹窗、主题色完全不知道数据从哪来**。这是这套代码里最好的设计，接任何新数据源都不用碰下游。

### 1.2 拉取参数（`config/scene.js` 实算值）

| 项 | 值 | 说明 |
|---|---|---|
| `OSM_BBOX` | `[39.984650, 116.474450, 39.996150, 116.488950]` | `[南, 西, 北, 东]`，Overpass 官方顺序 |
| 覆盖范围 | 约 **1237 m × 1271 m** | 园区外扩 50 米，正好一屏 |
| 中心点 | `116.4817, 39.9904`（北京望京） | 换城市只改 `CENTER`，bbox 自动联动 |

### 1.3 三个镜像 + 缓存

```js
// overpass.js
const ENDPOINTS = [
  'https://overpass.kumi.systems/api/interpreter',        // ① 社区镜像
  'https://maps.mail.ru/osm/tools/overpass/api/interpreter', // ② mail.ru
  'https://overpass-api.de/api/interpreter'               // ③ 官方主站
]
const CACHE_TTL = 7 * 24 * 60 * 60 * 1000                  // 7 天
cacheKey = 'osm-buildings:<bbox 保留 5 位小数>'             // localStorage
```

- 单镜像超时 **30 s**，查询内 `[timeout:25]`
- 命中缓存 → 零网络请求；写缓存失败（无痕模式/超配额）静默忽略
- 全部失败 → `throw`，由 `loadCity` 的 `catch` 降级

### 1.4 解析规则（`parseOsmResponse`）

| 规则 | 值 | 为什么 |
|---|---|---|
| 只取 `type === 'way'` | relation 多轮廓楼直接丢弃 | 数量少，解析成本高，白模收益低 |
| 跳过 `geometry` 里的 `null` 节点 | `if (!node) continue` | `out geom` 偶发未下载引用 |
| 相邻重复点去重 | 差值 < 1e-9 | 避免退化多边形 |
| 少于 4 点丢弃 | `ring.length < 4` | 不构成面 |
| **不闭合环** | 保留原始点序 | earcut 要求首尾不重复；`addBuilding` 里再统一剥一次 |

### 1.5 入库前的过滤（`buildFromOsm`）

```js
if (area < 30) continue      // 车棚/垃圾房，白模里是噪点
if (nearRoute(cx, cy)) continue  // 距巡检路线 0.00055°（≈61 m）内的不加载，给车让路
```

### 1.6 高度补全（`completeHeight`，四级递进）

| 优先级 | 来源 | 备注 |
|---|---|---|
| 1 | `tags.height` | 兼容 `"25"` / `"25 m"` / `"25米"`，有效区间 2–900 |
| 2 | `tags["building:levels"] × 3.2` | 中国常规层高，有效区间 0–150 层 |
| 3 | 建筑类型启发式 | 住宅 12–30 / 商办 12–34 / 厂房 5–11 / 未标注 9–33 |
| 4 | 中心区加成 | `max(0, 60 - dist×9000) × random` |
| 兜底 | 大底盘压平 | 面积 > 5000 ㎡ 时高度限 20 m；最终 `max(6, base)` |

> ⚠️ 已知缺陷：`Math.max(6, NaN)` 返回的是 **NaN**，不是 6。环里一旦有坏坐标，`dist` 变 NaN → 高度 NaN → `extrudedHeight: NaN` → Cesium **静默丢弃该栋**（不报错）。这是「实体数对得上但某几栋看不见」的成因之一。

## 2. 这次为什么没取到（2026-11-04 实测）

### 2.1 探测结果

| 端点 | HTTP | 耗时 | 结论 |
|---|---|---|---|
| `overpass.kumi.systems/api/status` | — (000) | 15 s 超时 | 不可达 |
| `maps.mail.ru/.../interpreter` | — (000) | 15 s 超时 | 不可达 |
| `overpass-api.de/api/status` | **406** | 1.0 s | 可达但被拦 |
| `z.overpass-api.de/api/status` | **406** | 1.0 s | 同上 |
| `lz4.overpass-api.de/api/status` | **406** | 0.7 s | 同上 |
| `overpass-api.openstreetmap.fr` | 000 | 20 s | 不可达 |
| `overpass.osm.ch/api/interpreter` | 200 | — | **可达，但只含瑞士数据**，北京返回 `elements: []` |
| `overpass.monicz.dev` | 307 → `private.coffee` | — | 重定向目标不可达 |

### 2.2 406 的定位

关键证据：**连 `/api/status` 这种无参数 GET 都返回 406**，而且返回体是 nginx 的默认错误页（156 字节），不是 Overpass 的 JSON 错误。

- 改 UA、加 `Accept: */*`、换 GET/POST、换极简查询 `node(1)` —— 全部 406
- 说明**不是查询语句写错**，是链路上有一层 nginx 在按域名/SNI 拦截并回 406

结论：**当前网络出口封了 `*.overpass-api.de` 家族和主流社区镜像**。换代码写法解决不了，只能换数据通道。

### 2.3 一分钟自证

1. 看左上角面板第二行「数据来源」：显示 `程序生成 · N 栋` = 走了降级；显示 `OSM 真实建筑轮廓 · N 栋` = 拉取成功
2. 控制台看 `[city] OSM 加载失败，降级为程序生成：` 后面的 Error 内容，`@ <url>` 会告诉你是哪个镜像挂的
3. 直接手工验：`curl -m 15 https://overpass-api.de/api/status`

## 3. 数据契约（接任何新数据源都必须满足）

`fetchOsmBuildings()` 的返回类型就是全部要求：

```ts
Array<{
  ring: number[][],   // [[lon, lat], ...] WGS84 度数，首尾不闭合，≥ 4 点
  tags: object        // 至少能读到 height / building:levels / building / name
}>
```

| 约束 | 违反的后果 |
|---|---|
| 坐标系 **WGS84** | 换成 GCJ-02（高德/腾讯）整体偏移 300–600 m，这不是 bug 是国内 GIS 第一大坑 |
| 环**不闭合** | 首尾重复点 → 零长度边 → earcut 三角化出问题（`addBuilding` 已做兜底剥离） |
| 环**不自交** | 自交会丢三角形（实测：蝴蝶结环从 6 个三角形掉到 5 个，但不会整栋消失） |
| 面积 ≥ 30 ㎡ | 车棚、门卫房会变成画面噪点 |
| 顶点顺序 | 顺时针/逆时针**都行**，Cesium 会自动纠正朝向 |

只要产出这个结构，`cityBase` 的编码（`WG-A01`）、三态高亮、弹窗、主题色全部零改动。

## 4. 五条可选数据源（含实测可达性）

| 方案 | 实测可达 | 含高度 | 离线可用 | 成本 | 接入改动 | 适用场景 |
|---|---|---|---|---|---|---|
| **A. Overpass API（现状）** | ❌ 三镜像全挂 | 部分（国内大量缺） | 否 | 免费 | 已实现 | 网络通畅时首选 |
| **B. 本地静态 JSON** | ✅ 不依赖网络 | 取决于导出时 | ✅ | 免费 | 小 | **推荐做兜底，演示/内网/断网都稳** |
| **C. 后端代理** | ✅ 取决于服务器 | 同 A | 可缓存 | 一台服务器 | 中 | 正式项目、多端复用、要限流 |
| **D. OpenFreeMap 矢量瓦片** | ✅ 200 | ✅ 有 `render_height` | 否（可本地化） | 免费无 key | 中 | **本机网络下的最佳替代** |
| **E. 3D Tiles / 商业白模** | 取决于供应商 | ✅ 真三维 | ✅ | 付费/自建 | 中（换 `cityBase.build`） | 验收要求真模型 |

### A. Overpass API

- 优点：一条 SQL-ish 查询拿全量轮廓，`out geom` 直接带坐标
- 缺点：公益服务，**限流严格**、国内网络不稳、只给轮廓不给高度
- 改良方向：换可达镜像（`osm.ch` 只覆盖瑞士，别用）、查询加 `[timeout:25]`、结果落 localStorage（已有）

### B. 本地静态 JSON（最稳的兜底）

把一次成功的结果固化成文件，启动优先读文件：

```
public/data/buildings-osm.json     ← [{ ring, tags }, ...] 约 100–300 KB / 130 栋
```

- 加载顺序：本地文件 → 命中就直接建模，**0 网络请求、0 等待、断网可用**
- 只有本地文件缺失才回落到 Overpass —— 演示现场不怕网络抽风
- 导出方式：在任意能联网的机器上跑一次脚本（见 §5.2），把产物提交进仓库

### C. 后端代理

```http
GET /api/buildings?bbox=39.984650,116.474450,39.996150,116.488950
→ 200 { "source": "osm", "cachedAt": 1730000000000, "items": [{ "ring": [[...]], "tags": {...} }] }
```

- 服务端拉 Overpass + 落库缓存，前端只认自己的域名 → 顺带解决 **CORS、限流、密钥、审计**
- 建议后端做**抽稀**（Douglas-Peucker，1–2 m 容差）再下发，数据量能降一个量级
- 内网部署时这是唯一正确解

### D. OpenFreeMap 矢量瓦片（本机网络实测可用）

**实测数据（2026-11-04）**

| 项 | 结果 |
|---|---|
| TileJSON | `https://tiles.openfreemap.org/planet` → 200，给出瓦片模板 |
| 北京 z14 瓦片 | `.../planet/20261101_080013_pt/14/13493/6203.pbf` → **200 / 65 KB** |
| `building` 图层 | ✅ 存在，字段 `colour, hide_3d, render_height, render_min_height` |
| 缩放范围 | **z13 – z14**（z15 返回空瓦片） |
| 密钥 | 不需要 |

- **关键收益：自带 `render_height`**，比 OSM 直接轮廓的高度补全靠谱得多
- 代价：需要 MVT 解码（`@mapbox/vector-tile` + `pbf`，约 30 KB），并做 **Web Mercator → WGS84** 反算
- z14 一格约 2.4 km × 1.6 km，覆盖一个园区绰绰有余；精度对白模足够（单栋轮廓误差 < 2 m）

### E. 3D Tiles / 商业白模

- 拿到 `osgb / obj / glTF` → 转 3D Tiles → `Cesium3DTileset.fromUrl()`
- 替换点只有 `cityBase.build()`，`destroy()` 改成 `scene.primitives.remove(tileset)`，其他模块不动
- 供应商方向：超图、51WORLD、图新地球；自建可用 Cesium ion 或 osgb2tiles

## 5. 推荐落地方案（✅ 已落地，2026-11-04）

> **当前状态**：本地快照方案已实现并通过无头浏览器截图验证——
> 面板显示「本地 OSM 快照 · 126 栋」，真实轮廓白模正常渲染。
> 数据文件 `public/data/buildings-osm.json`（133 栋 / 28 KB），由
> `scripts/fetch-buildings.mjs` 从 OpenFreeMap 矢量瓦片抽取生成。

### 5.1 加载优先级（三级）

```
本地静态 JSON  →  OpenFreeMap 瓦片 / Overpass  →  程序生成
   （0 延迟）        （联网时补真实轮廓）          （永远有东西看）
```

改造点集中在 `src/modules/cityBase.js` 的 `buildFromOsm()` 和新增的 `src/cesium/buildingSource.js`，`MapView` 只需改一行调用。

### 5.2 导出脚本（✅ 已实现：`scripts/fetch-buildings.mjs`，走 OpenFreeMap）

```bash
node scripts/fetch-buildings.mjs          # 默认 z14，产出 public/data/buildings-osm.json
node scripts/fetch-buildings.mjs --z 13   # 换更大范围时降低层级
```

脚本做的事：TileJSON 取最新瓦片模板 → 覆盖 bbox 的瓦片逐个解码 →
`building` 图层外环 → Mercator 转 WGS84 → 中心点裁剪 + 指纹去重 → 面积 < 30㎡ 丢弃 →
`render_height` 写入 `tags.height`（133 栋全部带真实高度，min/max/avg = 4/151/10.4 m）。

### 5.3 前端读本地文件（✅ 已实现：`cityBase.buildFromOsm`）

```js
// 数据取用顺序：本地快照 → Overpass 网络 → 抛错（触发程序生成降级）
const list = await resolveBuildingList({ bbox, localUrl })
// city.dataSource 现在会返回 'local' | 'osm' | 'generated'，MapView 据此显示面板文案
```

同时补了两处健壮性：
1. `completeHeight` 出口加 `Number.isFinite` 校验（`Math.max(6, NaN) === NaN` 会静默丢建筑）
2. `cityBase.destroy()` 置 `disposed` 标记，异步加载返回后不再往已销毁的 viewer 加实体

## 6. 坑清单

| 坑 | 现象 | 处理 |
|---|---|---|
| **坐标系混用** | 换高德/腾讯底图后建筑整体偏 300–600 m | 全链路 WGS84；或对业务数据做 GCJ-02 纠偏 |
| **ODbL 署名** | 法律风险，不是"可选" | 页面常驻 `© OpenStreetMap contributors`；当前 `global.css` 把 `.cesium-viewer-bottom` 隐藏了，靠日志推一条不够 |
| **Overpass 限流** | 429 / 504，刷新几次就挂 | 结果缓存 7 天（已有）；禁止高频刷新；正式项目走后端 |
| **CORS** | 浏览器直连被拦 | 走自己后端；OpenFreeMap 支持跨域 |
| **实体数量上限** | > 800 栋后帧率掉到 20 以下 | 每栋一个 `Entity` + `outline` ≈ 2 个 primitive；> 2000 栋改 `Primitive` + `GeometryInstance` 批渲染（10–50 倍差距） |
| **高度为 NaN** | 单栋静默消失，无任何报错 | `completeHeight` 出口加 `Number.isFinite` 校验，非法则回落 12 |
| **瓦片 z 上限** | OpenFreeMap z15 返回空瓦片 | 只请求 z13/z14，必要时用 z14 放大 |
| **环首尾闭合** | 三角化出零面积边 | `addBuilding` 已统一剥离，新数据源同样受益 |
